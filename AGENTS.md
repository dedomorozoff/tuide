# AGENTS.md

Правила для агентов, работающих в этом репозитории.

## Проект

`tuiDE` — desktop environment внутри терминала. Модуль `tuide`.
Go 1.26, Bubble Tea v2 (`charm.land/bubbletea/v2`),
lipgloss v2 (`charm.land/lipgloss/v2`).
Подробности и план: `ROADMAP.md`.

## Команды

```sh
go build ./...
go vet ./...
go test ./...
gofmt -l .
```

Прогон: `go run ./cmd/tuide`

## Архитектура

- Одна `tea.Model` на весь DE. **Вложенных `tea.Program` не бывает.**
  Приложение — обычная модель в дереве, получающая отфильтрованные `Msg`.
- Всё состояние — в моделях. Никаких глобальных переменных и пакетных синглтонов.
- `Update` не блокируется и не делает I/O. Долгая работа — в `tea.Cmd`, результат — в `Msg`.
- Всё платформенное живёт только в `internal/sys`. Наружу торчит один интерфейс на платформу.
  `runtime.GOOS` вне `internal/sys` не используется.
- Сборки: `*_windows.go`, `*_unix.go` вместо `if` внутри логики.

## Стиль

- Имя проекта: `tuiDE` в UI и документации, `tuide` в коде — модуль, бинарь,
  пути (`./cmd/tuide`), переменные окружения (`TUIDE_*`).
- Комментарии в коде не пишем, если явно не попросили.
- Имена — по смыслу, без сокращений ради экономии символов.
- Публичное — только то, что используется вне пакета.
- Ошибки оборачиваются с контекстом: `fmt.Errorf("wm: focus %s: %w", id, err)`.
- Линтер: стандартный `go vet`, плюс `gofmt`.

## Тесты

- Чистую логику (layout, снап, фокус, z-order, разбор клавиш) покрываем юнит-тестами.
- Рендеринг — golden-файлы: эталонный вывод в `testdata/`.
- Тест на каждом этапе из `ROADMAP.md`, а не после фичи.
- Список хоткеев и статус этапов — в `ROADMAP.md`; `UPDATE_GOLDEN=1` перегенерирует эталоны.

## Чего не делать

- Не тащить зависимости без нужды. Сначала проверь `go.mod`: там должно быть
  bubbletea, lipgloss и платформенные библиотеки.
- Не писать `TODO` в коде. Незавершённое — в `ROADMAP.md`.
- Не коммитить без явной просьбы.
