# tuiDE — terminal DE на Go + Bubble Tea v2

Цель: окружение рабочего стола внутри терминала — окна, тайлинг, лаунчер,
панель задач, терминал с настоящим PTY, файловый менеджер.

Стек: Go 1.26, `charm.land/bubbletea/v2`, `charm.land/lipgloss/v2`, PTY (Unix pty / Windows ConPTY).
Дистрибуция: один статический бинарь без рантайм-зависимостей.

## Решения, принятые на старте

- Платформы: **Windows + Unix с первого дня**. Весь платформенный код изолирован в `internal/sys`
  и разделён по файлам (`*_unix.go` / `*_windows.go`). Никаких `if runtime.GOOS ==` в логике.
- MVP: **WM + терминал + файловый менеджер**. Остальные приложения — после.
- Одна `tea.Model` на весь DE. **Никаких вложенных `tea.Program`** — приложения это обычные модели
  в дереве, получающие отфильтрованные `Msg` от композитора.

## Раскладка пакетов

```
  cmd/tuide/main.go
internal/
  geom/         прямоугольники, клампы, пересечения
  wm/           окна, фокус, z-order, воркспейсы, снап-зоны, тайлинг
  compositor/   экранный буфер, клетки со SGR, wide-графемы
  shell/        корневая tea.Model: роутинг ввода, drag/resize, оверлеи
  input/        keymap, биндинги
  appsdk/       интерфейс приложения + спецификация запуска
  apps/         welcome, clock, notes, calc, settings, term, files, editor, monitor
  theme/        палитры, стили, SGR-хелперы
  config/       JSON + XDG-пути
  sys/          пути, терминал, PTY, батарея; единственное место, знающее про платформу
  vt/           виртуальный терминал: VT state machine, буфер ячеек, scrollback
  fuzzy/        fuzzy-ранжирование строк
  textbuf/      редактируемый текстовый буфер с курсором
  expr/         парсер арифметических выражений (для calc)
```

`ipc` для внешних приложений появится в M6.

## Этапы

### M0 — Bootstrap ✅
go.mod, каркас пакетов, одно окно, тема, дефолтный keymap,
**корректный restore терминала при любом выходе и панике**.

Сделано: `geom`, `compositor` (клеточный экранный буфер со SGR-состоянием на ячейку),
`theme` (палитры + стили), `wm` (окна, фокус, z-order, maximize/minimize, hit-test),
`input` (keymap), `config` (JSON), `shell` (одна tea.Model), `apps/welcome`, `cmd/tuide`.
Тесты: юниты на геометрию, композитор, wm, keymap + golden-файлы рендера + e2e через
настоящий `tea.Program` на пайпах.

Готово: `tuide` открывает окно, ctrl+alt+q выходит, шелл не остаётся в битом состоянии.

### M1 — WM-ядро ✅
Окна, фокус, z-order, drag/resize мышью и клавишами, minimize/maximize,
снап (halves/quarters), master-stack тайлинг, воркспейсы, alt-tab.

Сделано:
- `wm`: 9 воркспейсов на окно (`Window.Workspace`), история фокуса (`FocusLast`),
  снап-зоны (`Zone`, `DropZone`, `Zone.Combine`), тайлинг master-stack
  (`Layout`, `mintLayout`, стабильный порядок по `Window.Opened`),
  регионы/края окна (`RegionAt`, `EdgesAt`) для мышиных жестов.
- `shell`: машина состояний drag/resize (`drag.go`), снап при отпускании у края
  рабочей области, оверлеи (`overlays.go`) — инспектор состояния и список окон
  для alt-tab, переключение воркспейсов и раскладки.
- `compositor`: `Clear` больше не переаллоцирует буфер каждый кадр.
- `input`: снап-хоткеи, раскладка, инспектор, воркспейсы и «отправить на
  воркспейс» по номерам.

Готово: 10 пустых окон, стабильный FPS (~740 кадров/с при 200×60, бенчмарки
`BenchmarkViewTenWindows*`), инспектор состояния по `ctrl+alt+d`.

#### Управление (M1)

| Клавиши | Действие |
| --- | --- |
| `ctrl+alt+←↑↓→` | двигать окно |
| `ctrl+alt+shift+←↑↓→` | ресайз окна |
| `ctrl+alt+h/j/k/l` | снап к левой/нижней/верхней/правой половине |
| `ctrl+alt+h` затем `ctrl+alt+k` | четверть (две перпендикулярные половины) |
| `ctrl+alt+c` | по центру |
| `ctrl+alt+t` | тайлинг master-stack вкл/выкл |
| `ctrl+alt+1..9` | переключить воркспейс |
| `ctrl+alt+shift+1..9` | отправить окно на воркспейс и перейти туда |
| `ctrl+alt+p` | вернуться к предыдущему окну |
| `alt+tab` / `alt+shift+tab` | цикл фокуса + список окон |
| `ctrl+alt+d` | инспектор состояния |
| `ctrl+alt+m` / `ctrl+alt+n` | maximize / minimize |
| `ctrl+alt+w` / `ctrl+alt+q` | закрыть окно / выйти |
| мышь: титул | перетаскивание; отпустить у края — снап |
| мышь: рамка/угол | ресайз |


### M2 — Shell UX ✅

Лаунчер с fuzzy-поиском, action palette, taskbar/dock, меню «Пуск»,
часы/батарея/сеть, встроенные приложения (notes, calc, settings), редактор конфига,
кнопки управления окнами.

Сделано:
- `shell/launcher.go`: общий оверлей для лаунчера приложений и палитры действий.
  Fuzzy-фильтр через `fuzzy.Rank`, навигация `↑/↓` с зацикливанием, `enter`
  запускает/выполняет, `esc` отменяет; пока оверлей открыт, клавиши не утекают
  в окна. `launch` при уже открытом окне фокусирует его, а не падает ошибкой.
- Таскбар (`shell/render.go`): кнопка «≡ start» открывает лаунчер, кнопки окон
  кликабельны (клик по фокусному — свернуть), порядок кнопок стабилен
  (по `Window.Opened`, не по стеку), справа статус-индикаторы сети/батареи,
  часы и подсказка. Раскладка таскбара — один источник (`taskbarItems`)
  и для рендера, и для hit-test.
- Тик раз в секунду: `shell` рассылает `appsdk.Tick` всем приложениям
  (окно Clock теперь живое) и рисует часы в таскбаре.
- `main.go`: зарегистрированы все встроенные приложения — welcome, clock, notes,
  calc, settings.
- Семантика старта: пустой `Launch` — пустой стол, приложения не открываются
  сами. Первый запуск без конфига открывает только welcome; явный пустой
  `"startup": []` в конфиге оставляет стол пустым.
- `apps/notes`: заметки на `textbuf` — мультистрочный редактор с курсором.
- `apps/calc`: калькулятор на `expr` — парсер арифметических выражений.
- `apps/settings`: интерактивное окно настроек (тема, таскбар, мышь)
  с живым применением в шелле и сохранением через `appsdk.RequestConfig`/`SaveConfig`.
- Индикаторы в таскбаре: сеть (`sys.Online()`, опрос раз в 30 сек) и батарея
  (`sys.Battery()` на Windows и Unix).
- Кнопки управления в заголовке окна: `[_] [^] [x]` в TitleRect для управления
  мышью (свернуть, развернуть, закрыть).

Готово: приложение открывается из лаунчера, переключается, настраивается через Settings; мышь полностью функциональна на окнах и панели задач.


#### Управление (M2)

| Клавиши | Действие |
| --- | --- |
| `ctrl+alt+space` | лаунчер приложений (fuzzy) |
| `ctrl+alt+a` | палитра действий (fuzzy) |
| `↑/↓` в оверлее | выбор строки, `enter` — выполнить, `esc` — закрыть |
| клик «≡ start» | открыть лаунчер |
| клик по кнопке окна | фокус окна; по фокусному — свернуть |

### M3 — Terminal ✅ (ConPTY на этой машине не поднимается)

Терминальное окно с настоящим PTY: `vim`, `htop`, `less` работают внутри
окна на обеих платформах.

**Pass-through решён**: в DE не осталось ни одной привязки на голый `Ctrl`.
`ctrl+q` → `ctrl+alt+q`, `ctrl+w` → `ctrl+alt+w`, всё остальное DE тоже на
`ctrl+alt`. Единственное исключение — `alt+tab`, его не биндит ни одна
программа в терминале.

#### M3.1 — PTY-драйвер (`internal/sys`)
- Unix: `creack/pty`, `Setsid` + `Setctty`, `SIGWINCH` через `Setsize`, `SIGHUP` на закрытии.
- Windows: ConPTY — `CreatePseudoConsole`, атрибут `PROC_THREAD_ATTRIBUTE_PSEUDOCONSOLE`,
  `EXTENDED_STARTUPINFO_PRESENT`, отсортированный UTF-16 блок окружения с
  принудительным `TERM=xterm-256color`, `WaitForSingleObject` в фоне для
  `Alive()`.
- Единый интерфейс: `PTY { Read, Write, Resize, Close }` + `ChildAlive`.

#### M3.2 — Виртуальный терминал (`internal/vt`)
Свой тонкий слой вместо `charmbracelet/x/vt`: нужен прямой доступ к клеткам.
- Парсер состояний по машине Пола Уильямса: ground / escape / CSI / OSC / DCS /
  SOS-PM-APC / UTF-8. Последовательности, разорванные между двумя `Write`,
  склеиваются корректно.
- Клетка хранит готовый SGR-префикс, поэтому `compositor` получает стиль
  бесплатно, а перерисовка соседей не может утечь цвет.
- SGR: атрибуты, 16/256 цветов, truecolor, underline color, reset каждого
  атрибута отдельно (`22`/`23`/`24`/`25`/`27`/`29`), framed/encircled/overline.
- Экраны: ED/EL/ICH/DCH/ECH/IL/DL/SU/SD, scrolling margins (DECSTBM), origin
  mode (DECOM), insert mode (IRM), autowrap (DECAWM).
- Alternate screen: 47/1047/1049 с сохранением курсора.
- Scrollback — кольцевой буфер на 5000 строк, постраничная прокрутка
  колесом и вьюпорт; при уменьшении окна строки уходят в историю, а не
  теряются.
- Курсор: DECSCUSR (блок/подчёркивание/бар, мигание), видимость (DECCKM),
  сохранение/восстановление (DECSC/DECRC), перерисовка поверх своей клетки.
- Ответы программе: `TakeReplies` для DSR, `CSI t`, DA; OSC 0/2 — заголовок
  окна, OSC 52 — буфер обмена, BEL — колокольчик.
- Wide-графемы: ширина по East Asian таблицам, комбинирующие знаки
  приклеиваются к предыдущей клетке, продолжение wide-руны не занимает символ.

#### M3.3 — Интеграция с композитором
- `compositor.BlitCells` принимает готовый `[]Cell` — терминал не строит
  строку кадра вообще.
- `appsdk.Painter` — опциональный интерфейс приложения: рисует прямо в
  прямоугольник окна. `appsdk.Named` — заголовок окна от программы.
- Замер: `BenchmarkBlitFullScreen` (200×50) — **273 мкс/кадр, 1 аллокация на
  кадр**. Для сравнения, кадр из десяти окон в 200×60 стоит 1.33 мс
  (`BenchmarkViewTenWindows`). Строка на кадр не собирается.

#### M3.4 — Ввод и pass-through
- Терминал получает всё, чего не забрал `input.Keymap`.
- Кодирование клавиш: C0-байты для `Ctrl`, escape-префикс для `Alt`,
  модификаторные CSI-последовательности (`ctrl+←` → `CSI 1;5D`), формы
  `DECCKM`/`DECKPAM` для стрелок, Shift+Tab, F1–F12, delete/pgup/pgdown.
- `appsdk.MouseConsumer`: пока программа внутри окна просит мышь
  (`?1000/?1002/?1003/?1006`), шелл не превращает её клики в drag/resize.
  Кодирование — SGR и legacy X10, координаты переводятся в клетки окна.
- Колесо: программе уходит отчёт, иначе — прокрутка скроллбека.
- Bracketed paste для вставки из буфера обмена.
- Ресайз окна → `appsdk.Frame` → `vt.Resize` + `PTY.Resize`.

Готово: терминал открывается из лаунчера, `vim`, `htop`, `less` работают
внутри окна, `ctrl+c`/`ctrl+w`/`ctrl+q` доходят до шелла. На Unix проверено
на живом PTY; **на Windows ConPTY в этой песочнице не поднимается** —
процесс падает с `0xC0000102` во всех восьми вариантах флагов
`CreateProcess`, вывод не идёт. Тест `internal/sys` в этом случае скипает,
а не падает. Код PTY на Windows остаётся непроверенным до машины, где
ConPTY работает.

#### Управление (M3)

| Клавиши | Действие |
| --- | --- |
| любая незанятая | уходит в терминал, включая `ctrl+c`, `ctrl+w`, `ctrl+q` |
| `ctrl+alt+q` | выход |
| `ctrl+alt+w` | закрыть окно |
| колесо | прокрутка скроллбека, пока программа не попросила мышь |
| `ctrl+shift+v` | вставка из буфера обмена (bracketed paste) |

### M4 — Приложения

Полноценные встроенные приложения для повседневной работы.

- **files**: двухпанельный файловый менеджер — навигация, превью текстовых
  файлов, операции (копирование, перемещение, удаление), диалог выбора файла.
- **editor**: текстовый редактор на базе `textbuf` — открытие/сохранение файлов,
  подсветка синтаксиса, поиск по тексту, номера строк.
- **monitor**: монитор ресурсов — CPU sparkline, память, список процессов
  с возможностью kill. Кроссплатформенно через `internal/sys`.

Готово: есть чем пользоваться каждый день.

### M5 — Полировка

Визуальные эффекты, UX-улучшения и удобство повседневного использования.

- Прозрачность неактивных окон (альфа-смешивание RGB фона между окнами).
- Анимации: плавное открытие/закрытие окон, переходы между воркспейсами.
- Темы и обои (фоновый паттерн из символов).
- Тосты / центр уведомлений — результат сохранения конфига, ошибки приложений,
  системные события.
- Автосохранение и восстановление сессии (`session.json`): геометрия окон,
  воркспейсы, открытые приложения, состояние тайлинга.
- Дополнительные раскладки тайлинга: vertical split, horizontal split, grid
  (сейчас только master-stack).
- Командная строка DE — режим `:` как в tmux/vim: `:new term`,
  `:set theme daylight`, `:kill`.
- Trей / system tray для фоновых приложений.

### M6 — Дистрибуция и инфраструктура

Один статический бинарь, CI, установщики, внешние плагины.

- **CI/CD**: GitHub Actions — `go vet`, `go test`, `gofmt`, `golangci-lint`
  на Linux, macOS и Windows. Проверка golden-файлов.
- **Сборка и релизы**: `goreleaser` — кросс-компиляция, tar/zip,
  манифесты Scoop (Windows), Homebrew (macOS), Nix.
- **IPC**: Unix domain socket / Windows named pipe, JSON-RPC протокол
  для внешних команд: `tuide-cli open htop`, скриптинг, плагины.
- **Документация**: man page, `--help` расширенный, примеры конфигов.

## Риски

1. **Терминальное окно = экранный буфер, а не отрендеренная строка.**
   Иначе M3 упрётся в потолок: скроллбек, курсор, resize, alt-screen не собрать.
   Композитор должен уметь копировать ANSI-буфер в окно и знать позицию курсора.
2. **Pass-through клавиш — блокер M3. _Решён в M3_.**
   `Ctrl+W` в bash удаляет слово, `Ctrl+C` прерывает процесс, `Ctrl+Q` — XON.
   Выбран первый вариант: DE живёт на `ctrl+alt+...`, привязок на голый
   `Ctrl` не осталось. `ctrl+q` → `ctrl+alt+q`, `ctrl+w` → `ctrl+alt+w`.
   `alt+tab` остался, потому что его не биндит ни одна программа в терминале.
3. **Совместимость терминалов.** truecolor и kitty-keyboard есть не везде —
   нужен degrade до 256/16 цветов и fallback раскладок клавиш.
4. **Windows.** PTY там — ConPTY, сигналы и ресайз ведут себя иначе.
   Весь этот зоопарк живёт в `internal/sys`, наружу торчит один интерфейс.
   На этой машине ConPTY не поднимается вообще: `CreatePseudoConsole`
   возвращает валидный хэндл, процесс падает с `0xC0000102`, вывод не идёт
   ни при одной комбинации `bInheritHandles`/`lpEnvironment`/`wShowWindow`.
   Проверить код PTY на Windows можно только на машине, где ConPTY работает.
5. **Перф.** Композиция строк на каждом кадре при 20 окнах упрётся быстро —
   мерять с первого дня, не откладывать. Замер M1: 10 окон при 200×60 —
   ~1.3 мс/кадр (`BenchmarkViewTenWindows`). Замер M3: блит терминала
   200×50 — 273 мкс/кадр при **одной аллокации на кадр**
   (`BenchmarkBlitFullScreen`), потому что `vt` отдаёт готовые `[]Cell`,
   а `screen.String()` по-прежнему остаётся единственным местом, где строка
   собирается. Кадр рабочего стола с терминальным окном — 858 мкс
   (`BenchmarkViewTerminal`).
6. **I/O в PTY.** Чтение из PTY должно быть в выделенной горутине через
   `tea.Cmd` / каналы. Блокирующий read в цикле событий заморозит весь DE.

## Правила

- Без комментариев в коде, если не попросят.
- Платформенное — только в `internal/sys`.
- Тест на каждый модуль WM: layout, фокус, снап — чистая логика, юнит-тестится.
